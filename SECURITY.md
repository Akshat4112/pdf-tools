# Security policy

PDF Tools is a browser-first application. Reports about unintended document transmission, data retention, malicious document handling, unsafe exports, or dependency vulnerabilities are especially valuable.

## Reporting a vulnerability

Use the repository's [Security tab](https://github.com/Akshat4112/pdf-tools/security). If GitHub private vulnerability reporting is enabled, submit the report there. If it is not available, do not post exploitable details or sensitive evidence in a public issue; request a private reporting channel in a minimal issue without disclosure details.

Include the affected commit or deployment, tool and browser version, a concise description of impact, and reproducible steps using synthetic files. Never send private PDFs, personal data, credentials, or sensitive screenshots.

No response-time guarantee or independent security certification is claimed. This policy describes the project's reporting procedure, not a guarantee that all vulnerabilities have been discovered.

## Scope and evidence

The current public deployment is the primary supported target; no historical version support window has been established. See the [privacy notice](https://akshat4112.github.io/pdf-tools/privacy/), [trust evidence](https://akshat4112.github.io/pdf-tools/trust/), [local-processing audit](docs/security/PT-SEC-002-local-processing-audit.md) and [supply-chain policy](docs/security/PT-SEC-003-supply-chain.md). Website hosting requests remain subject to GitHub Pages' data collection policy. Clearing a workspace is not secure erasure.
