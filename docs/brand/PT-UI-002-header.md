# PT-UI-002 — Branded responsive header/navigation

Uses the accepted FolioLocal lockup, scoped light/dark brand tokens and the existing path router. Shared on catalog, tool and not-found screens; future help/content screens should reuse SiteHeader. Logo assets use the GitHub Pages base path. Existing workspace styles and document geometry stay independent.

Desktop: home link, All tools, Categories disclosure, Privacy and Source. At 800 CSS px and below, a labelled Menu button controls the same navigation in document flow; expanding it pushes content down. Categories contains ordinary grouped links derived from implemented registry entries. It is a disclosure, not an ARIA application menu. Native Tab/Enter/Space work; Escape closes categories first and restores summary focus, then closes mobile navigation and restores button focus. Outside pointer interaction closes the disclosures. Route changes remount only the header to reset open state, including history navigation. No preferences or document data are stored.

Brand is announced once as “FolioLocal home”. All visible navigation controls have 44 px minimum targets and 3 px focus outlines. Assets follow system color scheme. Forced colors use system focus/borders. No animation is needed. Trust copy states “Free forever · Open source” and “PDF processing on your device. No account required.” It does not claim a completed security audit. Privacy explicitly links to the existing GitHub data-lifecycle specification until PT-REL-001 creates a public help/privacy route; Source links to the repository. Both destinations are labelled as on GitHub for assistive technology and marked with an external arrow.

Future language control: add a labelled language selector after Source in the same navigation, including the expanded mobile layout, when PT-UX-005 provides real translated routes/copy. Do not show inactive language options now. Full footer/homepage/workspace redesign and metadata remain separate tracker tasks.

Validation: dedicated Playwright coverage checks 320/390/768/1440 px in light/dark, logo loading, control bounds/target sizes, registry links, keyboard/Escape/focus, outside click, route/history resets and shared 404 chrome. Existing end-to-end workflows remain regression coverage for document processing. Browser checks run in CI when local Chromium is unavailable.
