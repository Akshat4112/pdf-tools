# PT-UI-006 — Processing and result UX

Shared panels now distinguish configuration, processing, verified output, failure and cancellation using the existing design tokens. No new branding palette or document persistence is introduced.

## Behavior

- Preview actions explain why they are unavailable with a linked accessible description. Split invalidates the old plan immediately when its input/settings change and enables processing only for the current resolved plan.
- Processing exposes a named progress bar and stage detail. Unknown startup work and final verification use an indeterminate indicator; measured intermediate progress uses the reported fraction. There are no fabricated time estimates or completion claims before verified output exists. Reduced-motion mode disables the moving indicator.
- Processing/outcome headings receive focus when their panel mounts, without moving focus on each progress update.
- Merge and Split subscribe to job state, ignore callbacks from replaced jobs and release their session on reset/exit. Cancellation updates immediately and late results are discarded. Queued jobs cancelled before execution never start; timeouts notify the UI before a delayed executor returns.
- Failure messages suggest recovery appropriate to the error category. **Review settings** returns to configuration while keeping selected files; **Start over** clears the workspace. Technical error codes remain available under Error details.
- **Adjust settings** on export results releases previous downloads/URLs and retains source files/settings. **Back to all tools** navigates to the catalog; it does not transfer document data to another tool.
- Results list verified files and actual generated byte sizes. Missing/unverified/inconsistent generic outputs do not expose download buttons. Merge/Split reuse a download URL on repeated downloads, then revoke it when adjusting, resetting or exiting.
- Image-result thumbnails load independently from verified downloads. Canvas failures explain that the download remains available. Cleanup guidance distinguishes workspace removal from deleting original or saved files.

## Verification

- Unit regressions cover queued cancellation, immediate timeout state, invalid progress, indeterminate/determinate semantics, invalid-output guards and recovery guidance.
- `app/e2e/processingStates.spec.ts` covers delayed Merge/Split jobs, cancel/adjust/rerun/reset, stale Split previews, malformed-input recovery, byte-size readback, reused/revoked download URLs, keyboard focus and result actions at 320px in both themes.
- Existing overlay/text recovery tests use the corrected action labels. The existing privacy, independent output and image-engine suites remain in CI.
- Browser checks run desktop Chromium and emulated mobile Chromium. Real-device and broader assistive-technology validation remain part of PT-QA-002/PT-UI-007.

This task does not claim secure memory erasure, sanitize exported PDF active content or implement the separate theme/workspace redesign task. It uses the current merged visual tokens, so an independent theme update can flow through those tokens.
