# PT-CORE-016 — Page numbers and text watermark

`/page-numbers/` and `/watermark/` add selectable text to a separately named, verified PDF copy. Files stay in memory on the device; the existing 50 MB / 300-page input limits and a 50 MB output limit apply. No uploads, persistence, OCR or original-text editing are introduced.

## Options and geometry

- Page numbers start at a positive integer and advance only on selected pages, in source document order. For selection `4, 2` starting at 7, page 2 receives 7 and page 4 receives 8. Other pages retain their original content and position.
- Watermarks support 1–120 normalized Unicode characters on one line, using a bundled English/German font. Unsupported characters block processing until edited or explicitly acknowledged for replacement with `?`, once per Unicode code point. No silent replacement/tofu.
- Both tools offer seven aligned anchors, font size 8–120 physical points, opacity 1–100%, margin 0–144 points and text color. Watermarks additionally offer a centered 45-degree diagonal.
- Layout uses the visible cropped page, including nonzero origins, intersection with the media box, all four intrinsic rotations and UserUnit. An inverse PDF.js viewport maps upright physical-point placement to original PDF coordinates. Font metrics and rotated bounding boxes are checked before drawing; text that cannot fit fails with a recovery instruction rather than clipping.
- The preview is a requested page of the actual full PDF generated by the same writer, preserved document catalog, embedded font, transform and settings as the final download. A page outside the selection previews unchanged. Preview generation checks every selected page, and Apply stays disabled until the requested page renders successfully.
- Text can cover existing content; the interface asks users to review placement. Modifying a copy can invalidate digital signatures, disclosed before Apply. Existing signatures are not claimed valid or preserved.

## Integrity and lifecycle

The writer modifies the loaded full document rather than rebuilding every page. Preflight collects source text, rotation and visible dimensions. After saving, a separate strict PDF.js readback checks page count, dimensions, rotations, original selectable text and expected overlay text before the shared output verification gate allows a download. These checks do not certify arbitrary annotation, form, bookmark or signature fidelity.

Each source/preview/result read uses a cancellable private PDF.js worker. A cancellation monitor begins before loading; pending text reads race abort, workers terminate on cancellation, and every page/document is cleaned up. Preview work is debounced, cancelled on settings/source changes, and guarded against stale completion. Full-job identity guards prevent late results after cancellation, reset or exit. Retry retains the source/settings; replacing the file resets ranges and preview page; full reset restores defaults. Repeated downloads reuse a tracked object URL, revoked on adjust/reset/exit. Rendering uses one bounded canvas (8 MB cap, at most 600×800).

## Font provenance

The embedded font is a 22,104-byte, renamed derivative **PDF Tools Sans**, generated from `@fontsource/noto-sans@5.3.0`, `files/noto-sans-latin-400-normal.woff`. Coverage is ASCII, Latin-1 and the available Euro/curly-quote/dash characters. Actual cmap coverage is generated alongside the asset; normalization uses NFC. This is deliberately limited English/German coverage, not arbitrary-script support.

The upstream SIL Open Font License 1.1 and copyright are shipped at `/pdf-tools/licenses/overlay-font.txt`. The modified font uses a distinct family and PostScript name. `scripts/build_overlay_font.py <path-to-source.woff>` regenerates the base64 TTF and coverage list using fontTools (validated with 4.61.1). The generated bytes are committed; fontTools and Fontsource are build-time preparation tools, not runtime dependencies. The font and MIT `@pdf-lib/fontkit@1.1.1` are dynamically loaded, self-hosted and subset again per output. Fontkit's notice is shipped at `/pdf-tools/licenses/fontkit.txt`. See the dependency ADR amendment.

## Verification

Unit tests exercise validation, explicit Unicode fallback, inverse transforms, cropped/rotated/UserUnit pages, selected-only sequencing, actual FontFile2 embedding, selectable German text, unchanged source bytes, independent output verification, cancellation and retry.

Desktop/mobile browser tests compare rendered pixels of each preview with its corresponding downloaded page across 0/90/180/270 degrees and UserUnit 2, check seven anchors plus diagonal, embedded German text and explicit unsupported fallback, fit/range/encryption recovery, source/reset defaults, URL reuse/revocation, and deliberately held worker text requests followed by cancellation/termination and retry. Requests are restricted to the test origin/data/blob; uncaught errors fail tests. Screenshots are opt-in temporary QA evidence.

Required gates: app/test/e2e TypeScript, lint, unit tests, production build, full desktop/mobile interface suite, image-engine regressions, dependency audit and corpus CI.
